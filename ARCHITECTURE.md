# ARCHITECTURE.md

`src/config/{db,logger}.js` (Mongoose connection, Winston logger) are shared infrastructure underpinning both feature modules, `src/transactions/` and `src/expense-splitting/`, each internally structured identically: `model → repository → service → controller → routes`, mounted onto `src/app.js` and started by `src/server.js`.

Data flow per request: `express.json()` parses the body, `src/middleware/auth.js` (currently a stub) resolves `req.user.id`, the feature's `routes.js` dispatches to `controller.js` (translates `req`/`res` only, no business logic), which calls `service.js` (all validation and money math — e.g. remainder-cent distribution, pairwise-balance netting), which calls `repository.js` (the *only* code allowed to touch a Mongoose model), which queries MongoDB. Errors thrown anywhere in the chain propagate via `next(err)` to `src/middleware/error-handler.js`.

This shape is fintech-appropriate on two axes. First, money integrity: every amount field is stored as `Number.isSafeInteger` cents, never a float, so split/settlement math (`Math.floor`/`%` remainder distribution, greedy debt netting) can never silently drop or invent a cent. Second, tenant isolation: every repository query is filtered by `req.user.id` (ownership) or `participants.userId` (membership) *at the query itself*, not just checked afterward in a controller — so an IDOR bug would require breaking the repository's own filter, not just forgetting a check one layer up. Deletes follow the same principle: cross-tenant bulk deletes are structurally forbidden; the one exception (`Transaction.deleteByUserId`) is scoped to the caller and guarded against an unfiltered wipeout if `userId` is ever falsy.

Key decisions: `getPendingBalances` computes balances on read (deterministic greedy settlement + signed pairwise aggregation) rather than persisting a running balance, so it can never drift from the underlying expense records; and the stub auth middleware is isolated to a single file so it can be swapped for real JWT/session auth without touching any business logic.
